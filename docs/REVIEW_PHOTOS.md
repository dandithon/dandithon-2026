# 리뷰 사진 첨부

## 요청 흐름

1. FE에서 사진 선택 → JPEG 변환/최대 1280px 축소 → EXIF·GPS 메타데이터 제거.
2. `POST /api/v1/review-photos`에 `multipart/form-data`로 `orderId`(서버 주문 ID), `file`(JPEG/PNG)을 전달한다. 브라우저가 multipart boundary를 생성한다.
3. 응답 예: `{ "success": true, "data": { "id": "UUID", "url": "/api/v1/review-photos/UUID" }, "error": null }`.
4. `POST /api/v1/reviews`의 `imageUrls`에 발급받은 상대 경로를 전달한다. 최대 5장. 사진을 첨부하지 않아도 기존 요청은 그대로 동작한다.
5. 이미지 표시는 상대 경로를 **백엔드 origin**에 연결한다. Vercel origin에 붙이지 않는다. `GET /api/v1/review-photos/{id}`는 JPEG 바이트를 반환한다.

## 검증과 저장

- 리뷰를 작성할 수 있는 공용 게스트 주문에만 업로드한다. 다른 주문의 사진을 붙이거나 이미 사용한 사진을 재사용하면 리뷰 저장을 거부한다.
- 파일별 최대 8MB, 요청 최대 9MB. 확장자를 신뢰하지 않고 ImageIO로 실제 JPEG/PNG를 판별한다. 최대 2,500만 화소, 저장본 최대 1280px·2MB. 서버도 새 JPEG로 인코딩하여 메타데이터를 보관하지 않는다.
- 사진은 기존 DB의 `review_photos` LONGBLOB에 저장한다. 외부 S3 계정·버킷·API 키는 추가로 필요하지 않다. 기존 DB의 영속성과 백업 정책이 사진에도 적용된다.
- 미사용 사진은 다음 업로드 때 24시간 경과분을 삭제한다. 동시에 보관하는 사진은 전체 200장, 주문당 미사용 20장까지로 제한한다. 장기 대용량 운영용 저장소는 아니며 시연 규모를 위한 제한이다.
- 리뷰 삭제 시 연결된 업로드 사진을 함께 삭제하고, 전체 시연 초기화도 업로드 사진을 삭제한다. URL은 임의 UUID이며 기존 공용 게스트 정책을 따른다. 개인정보·본인 인증 기능은 아니다.
- 업로드 성공 후 미리보기에서 제거하거나 작성 창을 닫으면 해당 사진은 미사용 상태로 남아 위 유효기간에 따라 정리된다. 업로드·리뷰 POST는 자동 재시도하지 않는다.
- HEIC/WebP는 FE 브라우저에서 JPEG로 변환할 수 있을 때 지원한다. 지원하지 않는 브라우저에서는 JPEG/PNG 선택 안내를 표시한다. 사진 방향은 브라우저 디코딩 결과를 사용하며 실제 iPhone 사진 검수는 필요하다.

## 배포

- 최신 BE 배포가 필요하다. 기존 업로드 API가 없는 서버에서는 FE가 첨부 버튼을 준비 상태로 표시한다.
- Flyway `R__review_photos.sql`은 독립 테이블을 생성하는 repeatable migration이다. 미병합 PR31의 V5/V6와 버전 충돌을 피한다. 기존 주문·리뷰 데이터는 변경하지 않는다.
- 별도 업로드 파일 볼륨은 필요 없지만, 기존 운영 DB가 영속적으로 설정되어 있어야 한다. MySQL/MariaDB 운영 환경의 실제 마이그레이션과 프록시 업로드 제한은 배포 후 확인한다.
- `docs/API.md`의 리뷰 사진 URL 계약과 함께 사용한다. 전체 지도 준비 화면과 실제 GPS 좌표 연결 제외 범위는 유지한다.
