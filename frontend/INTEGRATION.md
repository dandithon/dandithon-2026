# 조웅 담당 기능: 연동 인수인계

## 가게 진입과 미션 기록 분리 (PR #23 / 2026-11-05)

- 가게 상세는 초기 카탈로그 로딩의 `GET /stores/{storeId}` 결과로 즉시 표시한다. `POST /stores/{storeId}/browse`는 둘러보기 미션 기록용이며 상세 화면 진입의 선행 조건으로 사용하지 않는다.
- 미션 기록 API 미배포·네트워크 오류 시에도 가게 상세를 유지하고 기록 반영 여부를 확인하지 못했다는 안내만 표시한다. 실패 시 방문·미션 진행도를 임의로 올리거나 POST를 자동 재시도하지 않는다. 미션 기록 자체는 백엔드 API 배포가 필요하다.

## 시작·지도·가게 위치 개선 (PR #23 / 2026-11-05)

- Figma `ZMF98LwbRB9JGKbf6JjYsl`의 메인 `1:544` 및 제목 `2:12`를 브라우저에서 확인했다. 원본 제목 PNG를 `public/assets/start-market-title.png`로 내보내고 시안의 x64/y100, 273×91 크기를 적용했다. 배경과 시작 버튼은 기존 에셋을 유지한다.
- 전체 지도 버튼은 밝은 단색 배경의 ‘준비 중입니다!’ 안내와 닫기/시장 복귀를 제공한다. 기존 전체 지도 이미지·목록은 이 화면에서 표시하지 않는다.
- 가게 상세의 ‘위치 보기’는 현재 가게 ID로 시장의 해당 가게만 강조한다. 하이라이트는 opacity로 3회만 부드럽게 점멸하고, 동작 줄이기에서는 정적으로 표시한다.
- 위치 확인 중 캐릭터·GPS 이동 및 지도 조작·다른 가게 진입을 막고 보조 버튼을 숨긴다. 캐릭터 좌표는 변경하지 않는다. 복귀 버튼은 원래 가게 상세 및 탭으로 돌아가며 위치 보기 버튼에 포커스를 복원한다. 가게 상세 컴포넌트는 숨겨 유지하므로 시트 상태를 불필요하게 초기화하지 않는다.
- 강조 범위는 기존 게임 아트워크의 시각 좌표다. 실제 GPS 경로·실제 가게 좌표를 제공하는 기능이 아니다. 위치 미리보기·복귀에는 방문 API를 추가 호출하지 않는다.
- 로컬 모바일 390×740에서 제목·지도 준비 안내, 골목카페/서문분식 위치 강조·동일 가게 복귀, 미리보기 중 키 입력 이동 차단을 확인했다. 네 가게 및 짧은 화면 높이의 강조 범위는 자동 테스트로 확인한다. 실제 휴대폰 검수는 별도다.

## 코인·미션·장비 통합 개선 (PR #23 / 2026-11-05)

- 최신 main의 코인·초기화 API(PR #22) 및 일일 미션 변경(PR #20)을 통합했다. 백엔드는 수정하지 않았다.
- 코인 + 버튼에서 1,000 / 10,000 / 100,000 / 1,000,000 선택 또는 1~10,000,000 정수 직접 입력. 금액은 `POST /users/me/charge`에 그대로 보내고 반환 잔액을 App·market 캐시·프로필에 반영한다. 실패 후 자동 충전 재요청 없이 잔액 조회만 제공한다.
- 충전 창의 별도 ‘시연 데이터 초기화’ 메뉴는 코인 1,000·닉네임·레벨 복구와 주문·리뷰·구매 횟수·장비·배지·미션 기록 삭제 범위를 설명한다. 공용 게스트에 대한 영향과 되돌릴 수 없음을 확인한 후 체크해야 실행 가능하다.
- 초기화 POST 성공 후 로컬 장바구니·방문·미확정 주문 키를 정리하고 전체 시장·프로필을 다시 조회한다. 후속 조회 실패는 전체 로딩 오류 화면에서 GET 재조회하며 초기화 POST를 자동 재실행하지 않는다. 최신 백엔드 계약에 맞춰 즐겨찾기도 초기화한다.
- 최신 일일 미션: 가게 3곳 둘러보기 300 / 서문분식 리뷰 1개 200 / 모자 착용 100코인. 서버 응답으로 진행도·보상을 표시하고 수령 성공 시 잔액·수령 상태를 함께 갱신한다. 장비 변경 후 미션을 재조회하고 수동 새로고침도 제공한다.
- 우측 장비 슬롯은 머리·상의·신발·목도리 네 부위. 미착용은 흐리게, 착용 중에는 선명하게 표시하고 슬롯·가방 양쪽에서 착용/해제 가능하다. 잠금 상태에서는 착용할 수 없다.
- 프로필 앞·옆·뒤 미리보기와 시장 캐릭터는 같은 `progress.equipped`와 PlayerCharacter를 사용한다. 기존 방향별 atlas·슬롯별 합성·목도리 오버레이를 유지한다.
- 검증: 에셋 79개·테스트 40개·빌드 및 모바일 브라우저 검수. Mock에서 전체 장비 착용·신발/목도리 개별 해제, 앞/옆/뒤 표시, 전체 착용 상태 WASD 이동, 모자 미션 100코인 수령·중복 차단, 2,500 충전·한도 초과 차단, 초기화 후 1,000·미션·장비 잠금 복구 확인.
- 이전 검수에서 Cloudtype 무료 충전 1회(0→100,000)를 확인했다. 이번 확장 검수에서는 실제 공용 서버 초기화·추가 충전을 실행하지 않았다. 실제 iPhone·삼성 기기 검수는 별도다.
- 변경은 PR #23으로 검토하며 병합하지 않는다. 자동 Preview는 Mock 환경이다.

## 모바일 브라우저 하단 UI 대응 (2026-11-04)

Safari 하단 주소창에 조이스틱이 겹치는 문제를 수정했다. `100svh`와 safe-area padding으로 브라우저 UI가 펼쳐진 상태의 높이를 확보하고 VisualViewport resize를 감시한다. 시장은 가로폭을 유지하면서 표시 높이를 줄이며, 조이스틱·모드 전환 버튼의 그림과 입력 영역을 같은 오프셋으로 이동한다. 카메라 추적·드래그·확대 경계도 줄어든 표시 높이를 사용한다. 월드 좌표·충돌 데이터는 유지한다. 키보드 입력·브라우저 확대 중에는 VisualViewport 크기로 다시 축소하지 않는다.

시작·가게 화면은 전체 디자인이 보이도록 비율을 유지해 높이에 맞춘다. 높이가 충분한 휴대폰은 기존 표시를 유지하며, Android도 기종 판별 없이 보이는 높이 기준으로 계산한다. 테스트 27개·에셋 79개·빌드 통과. 브라우저 390×660과 412×780에서 하단 버튼과 가로·세로 넘침을 확인했다. 실제 iPhone Safari·삼성 인터넷 앱의 주소창 애니메이션·키보드 검수는 별도로 필요하다.

## PR #14 통합 이후 보완 (2026-11-04)

이 절은 아래 초기 인수인계보다 최신 상태다. `origin/main`의 PR #14(강보성 HTTP 연동)를 병합했고 기존 Vercel 설정과 모바일 너비 수정도 보존했다.

- 공통 `service.js`의 live/mock 전환과 기존 프로필 HTTP 구현을 그대로 사용한다.
- 구매·퀘스트 보상 성공 후 서버 프로필을 재조회해 구매 횟수·장비 잠금·배지·레벨·경험치·착용 상태를 갱신한다. 후속 조회 실패는 구매 실패로 처리하지 않으며, 기존 프로필을 유지하고 프로필 화면에서 재시도할 수 있다.
- 수집 음식은 현재 메뉴 목록이 아닌 서버 음식 목록을 기준으로 표시한다. 서버 배지 획득 여부를 로컬 횟수로 재판정하지 않는다.
- 서버 프로필과 공용 게스트 리뷰 안내를 표시한다. 단일 게스트 모델이며 개인 인증·리뷰 소유자 구분은 미지원이다.
- 서버의 혼잡도·NPC 수와 `mock` 표시를 사용하고, 대기시간 누락·음수·비정상 값은 정보 없음으로 표시한다. 현재 서버 대기시간은 카탈로그 시연 값이다.
- 검증: 에셋 79개, 테스트 24개, 프로덕션 빌드 통과. Cloudtype 사용자·장비·배지·가게·지도 조회 성공. 로컬 live 브라우저에서 시작→시장→프로필→수집 음식 및 서버 레벨·경험치·잠금·배지 표시 확인. 모바일 390×740에서 가로 넘침 없음 확인.
- 미검증: 이번 변경 이후 실제 서버 구매·닉네임 변경·장비 변경 등 쓰기 요청, 실제 휴대폰. 공용 서버 데이터는 이번 검수에서 변경하지 않았다.
- 남은 의존 사항: GPS 실측 기준점·실제 방문 검증, 레벨업 지급 정책. 현재 서버는 레벨·경험치 초기 표시값만 제공한다.
- 캐릭터는 현재 `PlayerCharacter.jsx`의 방향별 atlas 및 슬롯별 레이어 구현을 사용한다. 아래의 정면 세트만 제공된다는 초기 기록은 이전 상태이며, 신규 조합을 실기기에서 검수해야 한다.
- 공개 사이트는 아직 기존 Mock 배포다. 이번 변경은 로컬 브랜치에 있으며 자동 배포 연결·재배포는 조직 권한 해결 후 진행한다.

## 2026-11-04 배포 이후 작업

프론트엔드 Mock 데모를 https://ifyougotothemarket.vercel.app 에 배포했다. **실제 백엔드 API 연동은 별도로 반드시 진행해야 하며, 현재 배포는 서버 연동 완료를 의미하지 않는다.** Cloudtype 백엔드를 유지하면서 강보성의 공통 HTTP 기반에 조웅 담당 프로필·장비·배지·지도·혼잡도 화면을 연결한다. 서버 주소, 담당별 체크리스트와 자동 배포 미연결 상태는 [배포 문서](DEPLOYMENT.md)를 따른다.

## 강보성 파트와의 경계

- `src/api/market.js`와 가게·구매·리뷰·퀘스트의 API 구현은 변경하지 않았다.
- `App.jsx`에서 구매·리뷰·퀘스트 결과로 받은 공통 `state`를 프로필에도 전달한다. 프로필용으로 코인이나 주문을 다시 차감·생성하지 않는다.
- 조웅의 로컬 설정은 `src/api/exploration.js`, 구매 횟수·장비·배지의 시연 규칙은 `src/game/progression.js`로 분리했다.
- `hackton-market-demo-v1`: 기존 시장 상태. `dandithon-exploration-v1`: 닉네임·착용 설정. 프로필 초기화는 후자만 변경한다.
- 현재 내 리뷰에는 기존 데모의 사용자 리뷰를 표시한다. 실제 연동 시에는 서버가 인증 사용자 기준으로 반환한 리뷰만 전달해야 한다. 이름으로 작성자를 판별하지 않는다.
- 프론트엔드는 DB에 직접 연결하지 않는다. 실제 서버 연동은 공통 API 모듈을 통해 교체한다.

서버에서 횟수·장비·배지를 제공하면 로컬 주문 기록에서 다시 보상을 산출하지 않는다. 서버 연동 후에도 기존 localStorage 시연 데이터를 자동 업로드하거나 합산하지 않는다.

## 현재 Mock 규칙과 디자인 차이

- 구매 횟수는 중복되지 않은 성공 주문 메뉴 ID당 1회다. 한 번에 여러 개 구매한 수량을 횟수로 더하지 않는다. 초기 샘플 주문도 시연 구매 기록에 포함된다. 실제 구매 단위는 BE와 확정한다.
- 가방은 Figma `1:174`의 떡볶이 1/3/5/8회 조건을 사용한다. PRD의 장비 조건 표는 예시이므로 최종 지급 규칙은 합의가 필요하다. 배지 조건은 PRD의 3/5/10회다.
- 칼국수 장비는 원본처럼 잠금 자리만 표시한다. 확정되지 않은 아이템과 외형을 만들지 않았다.
- 전체 세트 정면을 제외한 장비 외형은 에셋 부족으로 미완료다. 개별 착용 상태는 저장되지만 외형이 완성된 것으로 표시하지 않는다.
- 레벨·경험치는 임의로 코인에서 환산하거나 지급하지 않는다. 현재는 준비 중 안내이며 규칙과 API가 필요하다.
- 혼잡도는 Figma 1/3/5/7명 표현을 사용한다. 현재 시연 구간은 5분 이하/10분 이하/20분 이하/20분 초과이며 최종 경계값은 미확정이다. 지도 NPC는 디자인이 제공된 서문분식에 표시하고, 다른 가게의 시연 대기시간은 목록에서 제공한다.
- 내 리뷰·수집 음식 탭과 GPS 상태 안내는 기존 공통 테마를 재사용한 기능 UI다. 해당 상세 디자인의 최종 대조가 필요하다.
- Figma 파일은 수정하지 않았다. 에셋 출처: `BIjA6jeCsy9WFTw8tR3RAG`, 전체 지도 `1:528`, 프로필 `1:174`, 혼잡도 `1:568`·`1:662`.

## GPS 연결

`src/game/mapCalibration.js`는 의도적으로 `null`이다. 현재 위치는 수신하되 서버 전송·위치 저장·방문 인증을 하지 않는다.

연결 시 서로 일직선이 아닌 실측 기준점 3개를 `anchors`에 제공한다. 각 기준점은 `latitude`, `longitude`, 원본 402×874 지도상의 `x`, `y`를 가진다. `maxAccuracy`에는 팀이 합의한 허용 오차(m)를 넣는다. 좌표 변환 함수는 부정확한 위치, 잘못된 설정, 지도 밖 좌표를 이동에 사용하지 않는다. 층수와 실내 위치 검증은 이 선형 변환만으로 해결되지 않는다.

가상 탐험과 실제 방문은 별개다. 기존 `marketApi.visit`는 가상 방문 데모이며 GPS 수신 성공을 해당 메서드에 연결하면 안 된다.
