# 저장소 공개 전 점검 결과

점검일: 2026-11-04 (KST)

## 판단

검사한 Git 기록과 현재 소스에서 실제 운영 비밀번호·API 토큰·개인키 유출은 발견하지 못했다. 다만 아래 개인정보 공개 범위와 공용 게스트 서버 운영 방식을 팀에서 확인한 뒤 공개를 결정해야 한다. 비밀정보 미탐지는 보안 보증 또는 운영 서비스 전체 보안 검증을 의미하지 않는다.

## 검사 범위와 방법

- `git fetch --all --prune` 후 모든 로컬·원격 추적 브랜치에서 도달 가능한 기록 검사. shallow clone이 아님을 확인.
- Gitleaks 8.30.1 기본 규칙으로 전체 Git 기록 34개 커밋과 현재 작업 디렉터리 검사. 공식 배포 파일의 SHA-256 체크섬 확인 후 실행. 보고서는 비밀값 100% 마스킹 옵션으로 임시 디렉터리에 저장.
- Git 전체 기록의 고유 blob 289개에서 민감 파일명·텍스트의 자격 증명 참조를 추가 검사.
- 현재 추적 파일의 환경 설정·API 코드·문서 및 Git 작성자 메타데이터 확인.
- GitHub 저장소 Secrets API에서 저장소 수준 Actions secret 0개 확인. 조직·환경 수준 secret과 Vercel·Cloudtype 내부 secret 값은 검사하지 않았다.
- 이미지·폰트·JAR 바이너리의 OCR·육안 전수 검사나 역분석은 하지 않았다. GitHub Issues·PR 대화·Actions 로그·첨부파일 전체와 삭제된 원격 브랜치의 서버 보관 객체는 범위 밖이다.

## 비밀번호·토큰 검사 결과

| 항목 | 결과 |
|---|---|
| 운영 DB 접속값 | `application-mysql.yml`은 `${DB_URL}`, `${DB_USERNAME}`, `${DB_PASSWORD}` 환경 변수 참조. 실제 값 하드코딩 없음 |
| 로컬·테스트 DB | H2 계정 `sa`, 빈 비밀번호. 운영 DB 비밀번호가 아니며 로컬·테스트 전용으로 유지 필요 |
| `.env`·인증서·개인키·DB 파일 | 검사한 Git 기록에서 실제 `.env`, 개인키·인증서 저장소, DB 데이터 파일 발견 안 됨. `.env.example`만 추적됨 |
| 프론트 환경 변수 예시 | 공개 가능한 데이터 모드와 HTTPS API 주소만 포함. API 주소는 인증 비밀값이 아님 |
| Gitleaks 탐지 1건 | `frontend/src/api/exploration.js:3`의 브라우저 localStorage 키 이름. 인증 토큰이 아닌 오탐으로 분류. 과거 기록과 현재 파일에서 같은 값 탐지 |
| 로컬 Vercel 연결 정보 | `.vercel/project.json`은 Git ignore 대상. 프로젝트·팀 ID 자체는 비밀번호가 아님. 토큰·사용자 인증 설정은 업로드 대상에 포함하지 않아야 함 |

## 공개 전에 팀이 확인할 사항

### 1. 커밋 작성자 개인정보

Git 작성자 기록에 팀원 실명·일반 이메일·학교 이메일이 있다. GitHub noreply 이메일만 있는 상태가 아니다. 보고서에는 실제 이메일 주소를 복사하지 않았다. 팀원의 기존 이메일 공개 의사를 확인해야 한다. 앞으로 noreply 이메일을 쓰더라도 과거 커밋의 이메일이 자동 변경되지는 않는다. 기록 변경이 필요하면 별도 협의 후 진행하며, 이번 검사에서는 이력을 수정하지 않았다.

### 2. 공용 게스트 서버 상태 변경

백엔드는 단일 게스트 userId 1을 공유하며, 사용자 인증 계층이 구현되어 있지 않다. 닉네임·장비·가상 주문·리뷰 등 쓰기 API가 같은 사용자 상태에 반영되는 구조다. 공개 소스를 통해 이를 쉽게 확인할 수 있으므로 운영 데이터·개인 데이터와 분리된 시연용 서버인지 확인해야 한다. 실사용자 서비스라면 사용자 식별·권한·요청 제한 등 별도 작업이 필요하다. 이 문제는 저장소 비공개만으로 보호되지 않는다.

`common/WebConfig.java`는 모든 Origin 패턴과 credentials를 허용한다. 실제 프론트 출처로 제한할지 백엔드 담당자와 검토한다. CORS는 API 사용자 인증을 대신하지 않는다. 이번 검사는 서버 쓰기 요청이나 공격 테스트를 수행하지 않았다.

### 3. 모노레포 전체와 디자인 자료

저장소 공개 시 frontend뿐 아니라 backend, 기획·역할 분담·개발 문서와 디자인 에셋도 함께 공개된다. Figma 참조 ID와 공개 서버 주소가 문서에 있다. 이들은 비밀번호는 아니지만 팀의 자료 공개 범위를 확인해야 한다. 폰트 저작권자의 라이선스 연락처는 팀원 개인정보와 구분하며 임의 삭제하지 않는다. 디자인 에셋의 외부 공개·재배포 권한 판단은 이번 비밀정보 검사에 포함하지 않았다.

## 공개 전 권장 순서

1. 팀원 이메일과 기획·디자인·백엔드 소스 공개 범위 확인.
2. 백엔드 담당자가 현재 Cloudtype가 공용 시연용인지 확인하고, 공유 상태 변경·CORS 정책 검토.
3. 관리자가 GitHub 웹의 Issues·PR·Actions 로그·첨부파일에 민감정보가 없는지 별도 확인.
4. 위 사항에 대한 팀 결정 후 관리자가 공개 여부 결정.

이 점검에서는 소스·서버 권한·저장소 공개 여부·Git 기록을 변경하지 않았다. 점검 보고서 파일만 추가했다.
